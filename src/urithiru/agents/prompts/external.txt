You are performing the external-verification stage of an MCTS scientific discovery evaluation. The engine already elicited P_search from prior evidence and literature, then tested the hypothesis on its seed dataset to obtain P_code. Before the evaluation's single MCTS update, the seed result was surprising enough to justify seeking independent evidence. Your task is to determine what the world outside the seed dataset says—not to confirm the seed result.

DOWNSTREAM USE
- A valid executed result becomes P_external on this MCTS node.
- Later hypothesis generation will use P_external instead of treating P_code as the final belief.
- The tree receives cost-adjusted information from the change between P_external and P_code. Precise confirmation and precise contradiction are therefore equally legitimate outcomes.
- If no defensible external test exists, return no external belief. The seed finding keeps its scientific reward and external verification adds nothing. Never force a proxy analysis merely to produce a result.

BELIEF CONTEXT
Hypothesis: $hypothesis
P_search: $p_search (belief after internal evidence and external literature, before seed data)
P_code: $p_code (belief after executed analysis on the seed dataset)
Seed dataset, which must not be reused: $dataset
Seed schema is supplied only for construct and measurement mapping.

EXTERNAL TEST
1. Search public repositories and relevant papers for observation-level data that directly measure every construct in the literal hypothesis. Do more than 10 web searches, and more than 5 science-specific ones. Mark a query as scientific when it targets literature or research data; the harness counts both totals and rejects a result below these thresholds.
2. The source must be independent: not the seed record, a mirror, derived table, overlapping sample, or the same collection campaign presented elsewhere.
3. Preserve the literal population and scope. Do not broaden a local claim, substitute a nearby construct, or invent an operational threshold to fit available data.
4. Before execution, identify one signed primary estimand that directly decides the claim. Check units, measurement compatibility, sample size, power, missingness, confounding, outliers, and a simple baseline.
5. If one dataset is valid, download it, save the analysis code, execute the test, and include the primary effect, uncertainty, and p-value in external_rationale.
6. Allocate exactly 30 votes across these likelihood categories from the external result:
   1. definitely false (score 0.0)
   2. maybe false (score 0.25)
   3. uncertain (score 0.50)
   4. maybe true (score 0.75)
   5. definitely true (score 1.0)
7. If no valid test executes, set external_category_counts to null, source to none, and explain the binding construct, independence, scope, estimand, power, or access failure.
